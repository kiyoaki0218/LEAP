LEAP 4択クイズ（`index.html` 単一ファイル構成）に、後から **古文単語330** を追加するための
「置き場所」と実装方針をまとめたもの。

- 現時点で **ユーザーの画面には一切出ない**（`KOBUN_CONFIG.enabled = false` のまま、`index.html` は未変更）
- データを入れて `enabled = true` にしたときだけ動く設計
- 既存の英単語機能（LocalStorage 保存・ショップ・称号・実績・苦手復習・辞典・学習状況フィルタ・PWA）を壊さないことを最優先

## 2. データ設計

### 1語の形式

```js
{
  id: 10001,                 // 10001〜10330（KOBUN_CONFIG.idBase から連番）
  word: "あはれなり",          // 見出し語（歴史的仮名遣い）
  reading: "あはれなり",       // 読み
  meaning: "しみじみと心を動かされる／趣がある",  // 現代語訳（複数は「／」区切り）
  part: 101,                 // 出題範囲（Part）のID
  subject: "kobun",          // 固定。英単語と区別するための種別
  pos: "形容動詞",             // 品詞
  conjugation: "ナリ活用",     // 活用の型（該当なしは空文字）
  frequency: 3,              // 頻出度 1〜3
  note: "係り結びに注意"        // 補足（任意）
}
```

### ID を 10001 からにする理由

- 既存の `PARTS` は ID 1〜2300 を予約済み（`Part 3: 1001〜1400`, `Part 4: 1401〜2000`, `+α: 2001〜2300`）
- 学習履歴は `userData.wordStats[id]`、苦手は `userData.weakWords[id]` と **ID をキーにした保存**なので、
  英単語と ID がぶつかると進捗が混ざる。**ID 空間を分けるのが最も安全**
- 10001 以上にすると `getDataIdRange()` が `1〜10330` を返すため、
  画面の「対応範囲」表示や入力上限は自動で広がる（コード変更不要）

### 章立てと Part 分割（確定）

古文単語330 は **5章・全330語** 構成。章ごとの語数が違うため、Part は章にそのまま対応させる
（等分割しない）。

| part | 範囲 | 章 | 冊内の通し番号 | 語数 |
|---|---|---|---|---|
| 101 | 10001–10050 | 1章 読解必修語 | 1〜50 | 50 |
| 102 | 10051–10150 | 2章 入試必修語 | 51〜150 | 100 |
| 103 | 10151–10180 | 3章 最重要敬語 | 151〜180 | 30 |
| 104 | 10181–10280 | 4章 入試重要語 | 181〜280 | 100 |
| 105 | 10281–10330 | 5章 入試攻略語 | 281〜330 | 50 |

#### 番号の対応ルール

冊子の通し番号（1〜330）とアプリ内 ID は **1対1** で対応させる。

```
id = 10001 + (冊内番号 - 1)     例: 冊内番号 1 → 10001 / 151 → 10151 / 330 → 10330
冊内番号 = id - 10000           例: 10151 → 151
```

- `kobun_words_data.js` の各エントリには、`id` に加えて **`num`（冊内番号 1〜330）** を持たせると
  紙の冊子と突き合わせやすい（スキーマに任意フィールドとして追加する）
- `part` は上の表の範囲で自動決定できる（`num` から一意に決まる）
  - 1〜50 → 101 / 51〜150 → 102 / 151〜180 → 103 / 181〜280 → 104 / 281〜330 → 105
- 章の並び順＝出題の難易度順なので、`id` を詰めて振れば辞典も冊子と同じ順に並ぶ

#### 表示名（案）

Part 名は章名をそのまま見せると学習者は迷わない。

```
古文 1章 読解必修語（50語）
古文 2章 入試必修語（100語）
古文 3章 最重要敬語（30語）
古文 4章 入試重要語（100語）
古文 5章 入試攻略語（50語）
```

> 注意: `kobun/kobun_config.js` の `parts` は**仮の等分割（各66語）**のままです。
> データ投入時に上の表へ差し替えてください（`desc` は `"1章 読解必修語"` など）。

## 3. 有効化するときの実装手順

### Step 1: データ投入

1. `kobun/kobun_words_data.js` の `KOBUN_WORDS_DATA` に330語を並べる
2. ブラウザのコンソールで検証（画面には出ない）

```js
KOBUN.validate(KOBUN_WORDS_DATA)   // → [] ならOK。エラー文が配列で返る
```

チェック内容：`word`/`meaning` の空、ID重複、ID範囲外、`part` と ID 範囲の食い違い。

### Step 2: `index.html` に読み込ませる

`<script src="./words_data.js"></script>` の直後に3行追加する。

```html
<script src="./kobun/kobun_config.js"></script>
<script src="./kobun/kobun_words_data.js"></script>
<script src="./kobun/kobun_loader.js"></script>
```

`kobun_config.js` の `enabled` を `true` にする。
**330語そろうまでは `kobun_loader.js` 側が統合を拒否する**（`console.warn` のみ、画面影響なし）。

### Step 3: `ALL_WORDS` への統合

`index.html` の以下を変更する（現在 972〜975 行あたり）。

```js
let ALL_WORDS = [];
if (typeof LEAP_WORDS_DATA !== 'undefined' && Array.isArray(LEAP_WORDS_DATA)) {
  ALL_WORDS = [...LEAP_WORDS_DATA];
}
// ↓ 追加
if (typeof KOBUN !== 'undefined') ALL_WORDS = KOBUN.merge(ALL_WORDS);
```

`KOBUN.merge()` は無効時にそのまま返すので、`enabled` を切り替えるだけで着脱できる。

### Step 4: `PARTS` に古文の範囲を足す

`index.html` の `const PARTS = [...]`（963行あたり）へ、`KOBUN_CONFIG.parts` を流し込む。

```js
const PARTS = [ /* 既存5件 */ ].concat(
  (typeof KOBUN_CONFIG !== 'undefined' && KOBUN_CONFIG.enabled) ? KOBUN_CONFIG.parts : []
);
```

これで範囲選択のPart一覧に「古文 Part 1〜5」が並ぶ（英語と古文を混ぜて選ぶことも可能）。
混ぜたくない場合は Step 5 の subject フィルタで制御する。

### Step 5: 種別（subject）で切り替える場合

英語と古文を「モード」で分けたいときは、範囲選択画面にトグルを1つ足す。

- `let quizSubject = "leap"` を追加（`subject` フィールドで絞る）
- `getQuizBasePool()` の戻り値に `.filter(w => (w.subject || "leap") === quizSubject)` を追加
- 辞典も同様に `renderDictionary()` の `words` を subject で絞る
- 出題プールを絞れば、ダミー選択肢も同じ subject から作られる（`startQuizWithPool` は `ALL_WORDS` 全体から
  ダミーを作るため、**混在を避けるならここも subject で絞る**こと）

```js
let candidates = ALL_WORDS.filter(w =>
  w.id !== targetWord.id && (w.subject || "leap") === (targetWord.subject || "leap")
);
```

### Step 6: 学習状況・苦手・実績

| 機能 | 影響 | 対応 |
|---|---|---|
| 学習状況（未学習/苦手/学習中/マスター） | `wordStats[id]` 参照なので ID 分離により自動で共存 | 変更不要 |
| 苦手復習 | `weakWords[id]` に `word`/`meaning` を保存済み | 変更不要 |
| 実績（累計正解数など） | 全 subject 合算になる | 分けたい場合のみ subject 別カウンタを追加 |
| 辞典のバッジ | ID ベース | 変更不要 |
| コイン／EXP／称号／ショップ | 共通通貨 | 分けるかは要検討（下記「未決定」） |

> 進捗を完全に分離したい場合は `KOBUN_CONFIG.storageKeys.progress` を使い、
> `userData` を subject ごとに分ける設計に切り替える（現状は同一 `userData` を共有する前提）。

### Step 7: Service Worker のキャッシュ

`sw.js` の `ASSETS` に3ファイルを追加し、`CACHE` のバージョンを上げる。

```js
"./kobun/kobun_config.js",
"./kobun/kobun_words_data.js",
"./kobun/kobun_loader.js"
```

## 4. データ準備の流れ（案）

1. 単語リスト（Excel か CSV）で列を確定：`見出し語 / 読み / 現代語訳 / 品詞 / 活用 / 頻出度 / 補足`
2. 現代語訳は「／」区切りに正規化（表記ゆれ・全角半角の統一）
3. 330語を Part の並び順（基本→頻出→名詞・副詞→敬語→和歌）に並べ替えてから ID を振る
4. JS へ変換（`JSON.stringify` して `KOBUN_WORDS_DATA` に貼る、または `words.json` を fetch する方式に合わせる）
5. `KOBUN.validate()` でエラー0件を確認
6. ローカルで `enabled = true` にして、範囲選択→クイズ→結果→辞典→学習状況フィルタを一通り確認

既存の `LEAP単語データ/words.json` と同じく、`kobun/kobun_words.json` を置いて
`fetch` フォールバックにする手もある（`checkAndFetchData()` を subject 対応にする必要あり）。
